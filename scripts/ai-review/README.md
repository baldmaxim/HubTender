# ai-review — ИИ-проверка находок «Проверки данных»

Скрипт на ПК, который видит офисную модель (Ollama / LM Studio / vLLM) или OpenRouter.
Берёт данные из портала по ключу API, просит модели оценить каждую открытую находку
(«по делу» / «похоже на шум» / «не уверен») и написать свои замечания по позициям, складывает
результат в `review.md`; после вашей разметки отправляет вердикты в портал.

Рабочий цикл: `ping` (один раз) → `run` (в конце сам вызывает `publish`) → вердикты «Ошибка»/«Норма» на
странице «Проверка данных» (рядом видны метки ИИ) → `sync` (вердикты в журнал для обучения) → правка
`AI-SKILLS.md`. Разметка `review.md` + `apply` остаётся запасным путём.

## Требования

- Node.js 18+ (проверено на Node 24). `npm install` не нужен: только встроенные модули.
- Windows и Linux.

## Настройка

1. Скопировать `ai-review.env.example` в `ai-review.env` (рядом, в `scripts/ai-review/`).
2. Заполнить: адрес и ключ портала, профили моделей (`AI_REVIEW_MODELS` и
   `AI_REVIEW_<ИМЯ>_*`).
3. Ключ портала выпускается в «Настройки → Доступ к API» с правами
   `tenders:read`, `verification:read`, `verification:write`.

Скрипт читает только `ai-review.env`; переменные окружения не учитываются.
Файл с ключами в git не попадает (`.gitignore`).

## Команды

```
node scripts/ai-review/review.mjs help
node scripts/ai-review/review.mjs ping [--models=qwen,minimax] [--quick] [--no-portal] [--bench=<тендер>]
node scripts/ai-review/review.mjs run <тендер> [--models=a,b] [--rule=U,V] [--new] [--max=N] [--remarks=N | --all] [--think] [--refresh] [--no-cache] [--no-publish]
node scripts/ai-review/review.mjs publish [каталог прогона] [--dry-run] [--no-auto]
node scripts/ai-review/review.mjs apply <путь к review.md> [--dry-run] [--brief]
node scripts/ai-review/review.mjs sync [каталог прогона] [--dry-run]
```

Код выхода: 0 — всё в порядке, 1 — сбой (портал, модель, отправка), 2 — ошибка настроек или флагов.

### ping

- портал: правила (`verification:read`) и список тендеров (`tenders:read`); право
  `verification:write` без записи не проверить — оно проверится при `apply`;
- каждая модель: есть ли она в `/models`, отвечает ли JSON по схеме, какой формат
  ответа принял сервер (`json_schema` → `json_object` → без формата);
- без `--quick` — контекст: промпт около 75 % от `AI_REVIEW_<ИМЯ>_CONTEXT` с
  контрольным кодом в начале; модель должна его вернуть. На медленной карте шаг
  занимает несколько минут;
- `--bench=<тендер>` вместо проверок — замер скорости: 20 первых позиций (в порядке `--max`),
  на каждой модели без кэша, сначала без рассуждений, затем с ними (если задан
  `AI_REVIEW_<ИМЯ>_THINK_EXTRA`). Печатает запросы, токены, время, токены выхода в секунду и
  прогноз на все открытые находки тендера. Ничего не пишет.

### run

`<тендер>` — номер (`256`, берётся последняя версия), номер с версией (`256v3`) или uuid.

| Флаг | Что делает |
| --- | --- |
| `--models=a,b` | профили моделей; по умолчанию — первая из `AI_REVIEW_MODELS`. Несколько моделей идут параллельно |
| `--rule=U,V` | только находки этих правил |
| `--new` | только новые находки (после последней отметки проверки) |
| `--max=N` | первые N позиций по наибольшей сумме Δ |
| `--remarks=N` | позиций без находок, отправляемых моделям для своих замечаний (самые дорогие, пока не набрано 80 % стоимости тендера). По умолчанию 20; при `--rule` и `--new` — 0 (явный `--remarks=N` сильнее) |
| `--all` | свои замечания по всем позициям со строками, без порога 80 % и потолка; несовместим с `--remarks=N` |
| `--think` | второй проход с рассуждениями для неуверенных и 20 самых дорогих находок (нужен `_THINK_EXTRA`, иначе пропускается с предупреждением) |
| `--refresh` | пересчитать отчёт портала перед разбором |
| `--no-cache` | не читать кэш ответов (писать в него продолжает) |
| `--no-publish` | не вызывать `publish` в конце прогона |

Берутся только находки без вердикта. Кроме оценки находок модель пишет **свои замечания**
(`remarks`): ошибки расчёта, которых правила не видят. Типы замечаний — записи `AI-…` в
`docs/data-quality/AI-SKILLS.md` (иначе тип `NEW` с названием). Замечание принимается, только
если подтверждено значениями из данных; не больше 3 на позицию; повтор находки правила
отбрасывается. Замечания пишутся по позициям с находками и по самым дорогим позициям без
находок (`--remarks=N`, `--all`).

**Расход запросов.** Каждая позиция без находок — это её данные в запросе к модели. Для
бесплатного OpenRouter (около 50 запросов в день) начинайте с `--remarks=20`; по офисной модели
число позиций ограничено только временем. Находки без позиции (по тендеру, материалу
справочника без строки) моделям не отправляются — они попадают в раздел «Без разбора».

Результат — папка `out/<номер>-v<версия>/<ГГГГ-ММ-ДД_ЧЧММ>/`:

- `review.md` — файл для разметки;
- `run.json` — состояние прогона (находки, оценки каждой модели, свои замечания ИИ `remarks`,
  версия промпта и навыков); по нему работает `apply`, править не нужно;
- `positions.json` — снимок разобранных позиций со строками (на что смотрела модель);
- после `publish` с автоотсевом и после `apply` — `applied.json` (что уже отправлено) и `itog.md` (итог).

`out/` в git не попадает.

### Разметка review.md

Находки сгруппированы по итоговой оценке: «По делу — ИИ считает ошибкой», «Похоже на шум»,
«Не уверен» (расхождения моделей первыми, с пометкой `⚡`), «Без разбора». Внутри — по сумме
Δ убыванию. Строка находки заканчивается ключом `‹f12›` — его не трогать.

Раздел «Новые замечания ИИ» стоит сразу после «По делу»: строки вида `AI-002 · поз. 12.3 «…»` или
`Новый тип «название» · поз. …`, ключ `‹n3›`, ниже — пояснение модели и данные, на которые она
опирается; по сумме позиции убыванию. Для замечаний `[+]` — замечание по делу, `[-]` — нет;
отметка раздела работает так же, как у находок.

- `[+]` (также `x`, `X`, `✓`) — согласен с ИИ, `[-]` — не согласен. В «Похоже на шум» `[+]` даёт
  вердикт портала «Норма», `[-]` — «Ошибка»; в остальных разделах (и где у ИИ нет мнения) `[+]` —
  «Ошибка», `[-]` — «Норма». Подсказка — в конце заголовка раздела;
- пусто — не решено, ничего не отправляется;
- комментарий — в конце строки после `//` (не путать с `https://`) или отдельной строкой
  `// …` под находкой; попадает в примечание вердикта;
- отметка в заголовке раздела (`## [+] …`) ставится всем неотмеченным строкам раздела;
  своя отметка строки сильнее. Такие вердикты получают примечание «ИИ-проверка (отметка раздела)»;
- непонятная отметка или чужой ключ — предупреждение, строка пропускается.

### publish

`publish [каталог прогона]` берёт `run.json` прогона (без аргумента — самый поздний прогон в `out/`;
можно указать и файл внутри папки), свежий отчёт портала и делает два дела. `run` вызывает его сам
в конце; сбой публикации — только предупреждение, файлы прогона уже записаны. Ключу нужно право
`verification:write`.

1. **Метки ИИ.** Метки «по делу» / «норма» / «не уверен» с причиной и фактами уходят пачками по 500 в
   `POST /tenders/{id}/verification/ai-assessments` и показываются на странице «Проверка данных».
   Отправляются только находки, которые есть в портале с тем же отпечатком; закрытые вердиктом и
   устаревшие сервер пропускает сам. Модель — все модели прогона через « + », версия промпта —
   `ext:<промпт>@<ревизия навыков>`. Повторный `publish` обновляет метки.
2. **Автоотсев шума.** Находка получает вердикт «Норма» (примечание `ИИ-авто: <код> — <причина>`), только
   если выполнено всё сразу:
   - итоговая оценка «норма», все ответившие модели с ней согласны, ни одна не понижена до «не уверен»;
   - основание (`basis`) у всех моделей одно и то же и это запись `docs/data-quality/AI-SKILLS.md`
     того же правила, что и находка, со `status: active` и **`auto: yes`**;
   - `|Δ|` строго меньше порога `AI_REVIEW_AUTO_MAX_RUB` (по умолчанию 100000 ₽); без суммы — не снимается;
   - в портале находка с тем же отпечатком и **без** вердикта: если человек уже поставил «Ошибка»
     или «Норма», её не трогают.

   **Как включить.** Скрипт и ИИ сами `auto: yes` не ставят — только человек правкой меты записи
   в `AI-SKILLS.md` (`<!-- kind: exception; rule: GA; status: active; auto: yes; … -->`). Коммит
   этой правки и есть согласие на автоотсев по записи. Остановить — `auto: paused` или `no`, либо
   `--no-auto` на один запуск. Вернуть снятую находку можно на странице кнопкой «Ошибка».

- `--dry-run` — печатает план (сколько меток, какие находки снялись бы), ничего не отправляет и не пишет;
- `--no-auto` — только метки, без автоотсева (и без чтения `AI-SKILLS.md`).

Автовердикты пишутся в `applied.json` (`auto: true`, `code`) и в `out/decisions.jsonl` строкой
`kind: "auto"`, `origin: "auto"`, `auto_code` — отдельно от ручных решений (`kind: "finding"`), чтобы
не смешиваться с ними при обучении на журнале. Повторный `publish` тот же автовердикт не шлёт.
В конце — строка «Метки ИИ: записано N, пропущено M; снято автоматически: K (по записям: GA-1 ×3, …)».

### apply

`apply <путь к review.md>` читает отметки и `run.json` рядом с файлом, берёт свежий отчёт
портала и для каждой отмеченной находки проверяет, что:

- находка ещё есть; её отпечаток не изменился («данные изменились после прогона»);
- в портале не стоит другой вердикт. Тот же вердикт — не отправляется.

Пропущенное выводится с причиной. Остальное уходит пачками по 500 в
`POST /tenders/{id}/quality/verdicts` с примечанием `ИИ-проверка[: комментарий]`.
Ошибка отправки — стоп и отчёт, журналируется только отправленное; повторный `apply`
доотправит остаток. Уже применённое (`applied.json`) пропускается молча.

- `--dry-run` — таблица того, что ушло бы, и причины пропусков; ничего не отправляет и не пишет;
- `--brief` — заменяет в выжимке тендера блок между строками `[ИИ-проверка …]` и
  `[/ИИ-проверка]` кратким итогом (нет блока — дописывает в конец); остальной текст
  выжимки не меняется.

Журнал решений — `out/decisions.jsonl` (пишут `apply` с `origin: "review"`, `publish` с `origin: "auto"` и `sync` с `origin: "page"`): по строке JSON на решение (время, тендер, правило,
сущность, отпечаток, оценки ИИ по моделям, решение, комментарий человека, признак
массовой отметки, версия промпта и навыков, ссылка на снимок позиции).

Отметки по замечаниям ИИ (`n…`) в портал **не отправляются**: `apply` записывает их только в
`applied.json` и в журнал строкой `kind: "remark"` (тип, название, позиция, строка, текст
замечания, модель, решение `confirmed`/`rejected`, комментарий), а в `itog.md` добавляет
счётчики и раздел «Замечания ИИ — подтверждено». Хранение замечаний в портале — позже.
`--dry-run` показывает их отдельным блоком; `--brief` их не учитывает.

### sync

`sync [каталог прогона]` забирает вердикты, которые вы поставили на странице «Проверка данных», в журнал
`out/decisions.jsonl` — для обучения. Без аргумента берёт самый поздний прогон в `out/`. В портал
ничего не отправляет (ключу достаточно `verification:read`).

Берёт `run.json`, `applied.json` и свежий отчёт портала. Запись в журнал (`kind: "finding"`,
`origin: "page"`, примечание — как на странице, без префикса «ИИ-массово») получает находка прогона, у которой
в портале тот же отпечаток и есть вердикт, кроме:

- примечание начинается с «ИИ-авто» — это автоотсев (он уже в журнале строкой `kind: "auto"`);
- примечание начинается с «ИИ-проверка» — вердикт пришёл из `apply`, он уже в журнале;
- решение уже есть в `applied.json` — повторный `sync` ничего не дублирует. Если вы передумали и решение
  другое — пишется новая запись;
- примечание «ИИ-массово…» — запись с `bulk: true` (массовая отметка, надёжность ниже).

**Откат автоотсева.** Находка, снятая автоматически и переставленная вами в «Ошибку», пишется в журнал
как ваше решение, а запись `AI-SKILLS.md`, по которой её сняли, получает `auto: paused` (автоотсев по ней
остановлен; в логе — предупреждение). Правку файла нужно закоммитить.

Решения попадают в `applied.json` прогона (`origin: "page"`) и в `itog.md`. В каталог прогона пишется
`sync.md` (перезаписывается): таблица согласия ИИ и вас по находкам с вердиктом («ИИ ошибка / вы норма»,
«ИИ норма / вы ошибка», «ИИ не уверен → …» и т. д.; снятое автоотсевом в таблицу не входит) и раздел
«Расхождения» с вашим примечанием, меткой, причиной и основанием ИИ и ссылкой на строку. Расхождения —
материал для правки навыков.

- `--dry-run` — печатает план и сводку, ничего не пишет (ни журнал, ни `applied.json`, ни `sync.md`,
  ни `AI-SKILLS.md`).

### Кэш

Ответы моделей кэшируются по позиции (оценки находок и замечания) в `out/cache/<профиль>/<ключ>.json`. Ключ — версия
промпта, ревизия навыков, модель, режим рассуждений, текст позиции и отпечатки её находок:
изменилось что-либо из этого — модель спрашивается заново, остальное берётся из кэша.
Если проход оборвался (сбой модели), уже полученное в кэше сохранено, повторный `run` продолжит с этого места.

### Промпт и навыки

Системный промпт — `prompts/review-v1.md` (версия `review-v1@<8 hex sha256 файла>`). В его конец
подставляются навыки проверяющего из `docs/data-quality/AI-SKILLS.md` — только по правилам,
которые есть в прогоне. Правка промпта или навыков меняет ключ кэша.

## Профили моделей (необязательные ключи)

- `AI_REVIEW_<ИМЯ>_EXTRA` — JSON-объект, вливается в тело каждого запроса (например, отключить рассуждения);
- `AI_REVIEW_<ИМЯ>_THINK_EXTRA` — JSON-объект, вливается поверх `EXTRA` во втором проходе `--think`;
- `AI_REVIEW_<ИМЯ>_BATCH_FINDINGS` — максимум находок в одной пачке (60).

Размер пачки также ограничен `CONTEXT` (на промпт, данные и резерв ответа) и `MAX_TOKENS`
(на ответ примерно по 200 токенов на находку и по 300 на позицию — под замечания).

## Типичные проблемы

- **Контрольный код не совпал.** Модель видит меньше контекста. Ollama молча
  обрезает начало — поднимите `OLLAMA_CONTEXT_LENGTH` / `num_ctx`; LM Studio — Context
  Length при загрузке модели; vLLM — `--max-model-len`.
- **429 у бесплатного OpenRouter.** Лимит около 20 запросов в минуту и 50 в день;
  скрипт повторяет запрос с паузами, но дневной лимит обойти нельзя.
- **Данные тендера уходят в OpenRouter.** Это внешний сервис — решайте по
  приватности; для закрытых тендеров используйте только офисную модель.
- **Модель не видна с этой машины.** Запускайте скрипт на ПК, который её видит.
- **Таймаут.** Увеличьте `AI_REVIEW_<ИМЯ>_TIMEOUT_SEC`.
- **«ответил не портал (HTML)».** Проверьте `TENDERHUB_API_URL`: портал — `https://gp.su10.ru`
  (`tender.su10.ru` теперь чужой сервер, скрипт его не принимает).
