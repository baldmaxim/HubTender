# ai-review — ИИ-проверка находок «Проверки данных»

Скрипт на ПК, который видит офисную модель (Ollama / LM Studio / vLLM) или OpenRouter.
Берёт данные из портала по ключу API, просит модели оценить каждую открытую находку
(«по делу» / «похоже на шум» / «не уверен»), складывает результат в `review.md`; после
вашей разметки отправляет вердикты в портал.

Рабочий цикл: `ping` (один раз) → `run` → разметка `review.md` → `apply`.

## Требования

- Node.js 18+ (проверено на Node 24). `npm install` не нужен: только встроенные модули.
- Windows и Linux.

## Настройка

1. Скопировать `ai-review.env.example` в `ai-review.env` (рядом, в `scripts/ai-review/`).
2. Заполнить: адрес и ключ портала, профили моделей (`AI_REVIEW_MODELS` и
   `AI_REVIEW_<ИМЯ>_*`).
3. Ключ портала выпускается в «Настройки → Доступ к API» с правами
   `tenders:read`, `verification:read`, `verification:write`.

Скрипт читает только `ai-review.env`; переменные окружения не учитываются.
Файл с ключами в git не попадает (`.gitignore`).

## Команды

```
node scripts/ai-review/review.mjs help
node scripts/ai-review/review.mjs ping [--models=qwen,minimax] [--quick] [--no-portal] [--bench=<тендер>]
node scripts/ai-review/review.mjs run <тендер> [--models=a,b] [--rule=U,V] [--new] [--max=N] [--think] [--refresh] [--no-cache]
node scripts/ai-review/review.mjs apply <путь к review.md> [--dry-run] [--brief]
```

Код выхода: 0 — всё в порядке, 1 — сбой (портал, модель, отправка), 2 — ошибка настроек или флагов.

### ping

- портал: правила (`verification:read`) и список тендеров (`tenders:read`); право
  `verification:write` без записи не проверить — оно проверится при `apply`;
- каждая модель: есть ли она в `/models`, отвечает ли JSON по схеме, какой формат
  ответа принял сервер (`json_schema` → `json_object` → без формата);
- без `--quick` — контекст: промпт около 75 % от `AI_REVIEW_<ИМЯ>_CONTEXT` с
  контрольным кодом в начале; модель должна его вернуть. На медленной карте шаг
  занимает несколько минут;
- `--bench=<тендер>` вместо проверок — замер скорости: 20 первых позиций (в порядке `--max`),
  на каждой модели без кэша, сначала без рассуждений, затем с ними (если задан
  `AI_REVIEW_<ИМЯ>_THINK_EXTRA`). Печатает запросы, токены, время, токены выхода в секунду и
  прогноз на все открытые находки тендера. Ничего не пишет.

### run

`<тендер>` — номер (`256`, берётся последняя версия), номер с версией (`256v3`) или uuid.

| Флаг | Что делает |
| --- | --- |
| `--models=a,b` | профили моделей; по умолчанию — первая из `AI_REVIEW_MODELS`. Несколько моделей идут параллельно |
| `--rule=U,V` | только находки этих правил |
| `--new` | только новые находки (после последней отметки проверки) |
| `--max=N` | первые N позиций по наибольшей сумме Δ |
| `--think` | второй проход с рассуждениями для неуверенных и 20 самых дорогих находок (нужен `_THINK_EXTRA`, иначе пропускается с предупреждением) |
| `--refresh` | пересчитать отчёт портала перед разбором |
| `--no-cache` | не читать кэш ответов (писать в него продолжает) |

Берутся только находки без вердикта. Находки без позиции (по тендеру, материалу
справочника без строки) моделям не отправляются — они попадают в раздел «Без разбора».

Результат — папка `out/<номер>-v<версия>/<ГГГГ-ММ-ДД_ЧЧММ>/`:

- `review.md` — файл для разметки;
- `run.json` — состояние прогона (находки, оценки каждой модели, версия промпта и навыков);
  по нему работает `apply`, править не нужно;
- `positions.json` — снимок разобранных позиций со строками (на что смотрела модель);
- после `apply` — `applied.json` (что уже отправлено) и `itog.md` (итог).

`out/` в git не попадает.

### Разметка review.md

Находки сгруппированы по итоговой оценке: «По делу — ИИ считает ошибкой», «Похоже на шум»,
«Не уверен» (расхождения моделей первыми, с пометкой `⚡`), «Без разбора». Внутри — по сумме
Δ убыванию. Строка находки заканчивается ключом `‹f12›` — его не трогать.

- `[+]` (также `x`, `X`, `✓`) — по делу, вердикт портала «Ошибка»;
- `[-]` — не по делу, вердикт «Норма»;
- пусто — не решено, ничего не отправляется;
- комментарий — в конце строки после `//` (не путать с `https://`) или отдельной строкой
  `// …` под находкой; попадает в примечание вердикта;
- отметка в заголовке раздела (`## [+] …`) ставится всем неотмеченным строкам раздела;
  своя отметка строки сильнее. Такие вердикты получают примечание «ИИ-проверка (отметка раздела)»;
- непонятная отметка или чужой ключ — предупреждение, строка пропускается.

### apply

`apply <путь к review.md>` читает отметки и `run.json` рядом с файлом, берёт свежий отчёт
портала и для каждой отмеченной находки проверяет, что:

- находка ещё есть; её отпечаток не изменился («данные изменились после прогона»);
- в портале не стоит другой вердикт. Тот же вердикт — не отправляется.

Пропущенное выводится с причиной. Остальное уходит пачками по 500 в
`POST /tenders/{id}/quality/verdicts` с примечанием `ИИ-проверка[: комментарий]`.
Ошибка отправки — стоп и отчёт, журналируется только отправленное; повторный `apply`
доотправит остаток. Уже применённое (`applied.json`) пропускается молча.

- `--dry-run` — таблица того, что ушло бы, и причины пропусков; ничего не отправляет и не пишет;
- `--brief` — заменяет в выжимке тендера блок между строками `[ИИ-проверка …]` и
  `[/ИИ-проверка]` кратким итогом (нет блока — дописывает в конец); остальной текст
  выжимки не меняется.

Журнал решений — `out/decisions.jsonl`: по строке JSON на решение (время, тендер, правило,
сущность, отпечаток, оценки ИИ по моделям, решение, комментарий человека, признак
массовой отметки, версия промпта и навыков, ссылка на снимок позиции).

### Кэш

Ответы моделей кэшируются по позиции в `out/cache/<профиль>/<ключ>.json`. Ключ — версия
промпта, ревизия навыков, модель, режим рассуждений, текст позиции и отпечатки её находок:
изменилось что-либо из этого — модель спрашивается заново, остальное берётся из кэша.
Если проход оборвался (сбой модели), уже полученное в кэше сохранено, повторный `run` продолжит с этого места.

### Промпт и навыки

Системный промпт — `prompts/review-v1.md` (версия `review-v1@<8 hex sha256 файла>`). В его конец
подставляются навыки проверяющего из `docs/data-quality/AI-SKILLS.md` — только по правилам,
которые есть в прогоне. Правка промпта или навыков меняет ключ кэша.

## Профили моделей (необязательные ключи)

- `AI_REVIEW_<ИМЯ>_EXTRA` — JSON-объект, вливается в тело каждого запроса (например, отключить рассуждения);
- `AI_REVIEW_<ИМЯ>_THINK_EXTRA` — JSON-объект, вливается поверх `EXTRA` во втором проходе `--think`;
- `AI_REVIEW_<ИМЯ>_BATCH_FINDINGS` — максимум находок в одной пачке (60).

Размер пачки также ограничен `CONTEXT` (на промпт, данные и резерв ответа) и `MAX_TOKENS`
(на ответ примерно по 200 токенов на находку).

## Типичные проблемы

- **Контрольный код не совпал.** Модель видит меньше контекста. Ollama молча
  обрезает начало — поднимите `OLLAMA_CONTEXT_LENGTH` / `num_ctx`; LM Studio — Context
  Length при загрузке модели; vLLM — `--max-model-len`.
- **429 у бесплатного OpenRouter.** Лимит около 20 запросов в минуту и 50 в день;
  скрипт повторяет запрос с паузами, но дневной лимит обойти нельзя.
- **Данные тендера уходят в OpenRouter.** Это внешний сервис — решайте по
  приватности; для закрытых тендеров используйте только офисную модель.
- **Модель не видна с этой машины.** Запускайте скрипт на ПК, который её видит.
- **Таймаут.** Увеличьте `AI_REVIEW_<ИМЯ>_TIMEOUT_SEC`.
- **«ответил не портал (HTML)».** Проверьте `TENDERHUB_API_URL`: портал — `https://gp.su10.ru`
  (`tender.su10.ru` теперь чужой сервер, скрипт его не принимает).
