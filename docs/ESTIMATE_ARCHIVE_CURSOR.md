# Подключение Cursor к API архива смет

Пошагово: выпустить ключ, положить его в окружение, проверить связь, научить агента
Cursor им пользоваться. Всё, что ниже, проверено на живом стенде — бэкенд, ключ,
области доступа и журнал вызовов.

Справочник по самому API: [ESTIMATE_ARCHIVE_API.md](ESTIMATE_ARCHIVE_API.md).

> **Перед первым подключением** убедитесь, что миграция применена к базе, с которой
> работает бэкенд, иначе все три админских эндпоинта и страница «Доступ к API» ответят 500:
> ```sql
> SELECT to_regclass('public.api_keys'),
>        to_regclass('public.api_access_settings'),
>        to_regclass('public.api_call_log');
> ```
> Три `NULL` → применить `db/yandex/incremental/2026_08_api_access_control.sql`.

## Шаг 1. Выпустить ключ

**Настройки → Доступ к API → Ключи → Выпустить ключ**. Страница доступна ролям
`administrator` и `developer`.

| Поле | Что выбрать для Cursor |
|---|---|
| Название | «Cursor, <имя>» — чтобы потом было понятно, чей ключ отзывать |
| Права | «Чтение архива смет». «Позиции тендера» — если агент должен выбирать тендер и писать в существующие позиции: без него он не узнает их id. «Сборка смет» — только если агент действительно должен писать в тендеры. «Запись строк тендера» — прямая запись строк без архива, только для ключей с ограничением по тендерам |
| Разрешённые тендеры | Оставьте пустым для чтения; для записи впишите конкретные ID |
| Действует до | Поставьте дату. Бессрочный ключ на рабочей машине — плохая идея |

Секрет вида `thk_…` показывается **один раз**. В базе хранится только SHA-256 хеш:
потерянный ключ не восстанавливается ни из бэкапа, ни через поддержку — выпускается новый.

## Шаг 2. Положить ключ в окружение

Ключ читается только из переменных окружения. В аргументы команд он не передаётся —
иначе осел бы в истории шелла и в логах агента.

**PowerShell (Windows), на постоянно:**
```powershell
setx TENDERHUB_API_KEY "thk_..."
setx TENDERHUB_API_URL "https://tender.su10.ru"
```
После `setx` перезапустите Cursor — уже открытые окна старое окружение не подхватят.

**bash / zsh:**
```bash
echo 'export TENDERHUB_API_KEY="thk_..."' >> ~/.bashrc
echo 'export TENDERHUB_API_URL="https://tender.su10.ru"' >> ~/.bashrc
```

Не кладите ключ в файлы репозитория: ни в `.env`, ни в `.cursor/mcp.json`, ни в правила.
`.env*` уже в `.gitignore`, но ключ в них всё равно не нужен — переменных окружения достаточно.

## Шаг 3. Проверить связь

```bash
node scripts/archive-api.mjs search "устройство стяжки" --unit=м2 --limit=5
```

Ожидаемо: JSON-массив (пустой `[]`, если по этому запросу в архиве ничего нет) — это
уже успех, связь и ключ работают. Другие ответы:

| Что видно | Причина |
|---|---|
| `Не задан TENDERHUB_API_KEY` | Переменная не подхватилась — перезапустите терминал/Cursor |
| `Не удалось соединиться` | Неверный `TENDERHUB_API_URL`, нет сети или бэкенд не запущен |
| `HTTP 401` | Ключ отозван, просрочен или скопирован с ошибкой |
| `HTTP 403 [API_KEY_SCOPE_DENIED]` | Ключу не выдана нужная область |
| `HTTP 503 [ENDPOINT_DISABLED]` | Эндпоинт выключен в «Настройки → Доступ к API» |
| `ответ не JSON` | Ответил прокси, а не приложение — проверьте адрес и доступность хоста |

## Шаг 4. Подключить к Cursor

### Вариант A — правило проекта (рекомендуемый)

В репозитории уже лежит [`.cursor/rules/estimate-archive-api.mdc`](../.cursor/rules/estimate-archive-api.mdc):
агент знает команды CLI, порядок «сначала проба, потом запись» и разбор ошибок.
Отдельной настройки не требуется — Cursor подхватывает правила из проекта.

Проверка: спросите у агента «найди в архиве смет позиции про устройство стяжки» —
он должен сам вызвать `node scripts/archive-api.mjs search …`.

Почему так, а не MCP: API вызывается обычным HTTP из терминала, ключ живёт в
окружении, ничего дополнительно устанавливать и обновлять не нужно.

### Вариант B — MCP-сервер поверх OpenAPI

Если хочется, чтобы эндпоинты были у агента отдельными инструментами, а не командами
терминала, поднимите универсальный мост OpenAPI → MCP. Спека отдаётся живым сервисом:

```bash
node scripts/archive-api.mjs spec > archive-openapi.yaml
```

Конфиг Cursor (`.cursor/mcp.json` в проекте или `~/.cursor/mcp.json` глобально) имеет вид:

```jsonc
{
  "mcpServers": {
    "tenderhub-archive": {
      "command": "npx",
      "args": ["-y", "<пакет-мост>", "--spec", "./archive-openapi.yaml"],
      "env": {
        "TENDERHUB_API_URL": "https://tender.su10.ru",
        "TENDERHUB_API_KEY": "${env:TENDERHUB_API_KEY}"
      }
    }
  }
}
```

Честно: конкретный пакет-мост я не проверял — их несколько, они быстро меняются, и
выбирать стоит по свежести и по тому, умеет ли он прокидывать заголовок `X-API-Key`.
Форма конфига и путь к спеке верны, остальное проверяйте при установке. Ключ в файл
не вписывайте — только ссылкой на переменную окружения.

## Что ключ может и чего не может

| Действие | По ключу |
|---|---|
| Поиск по архиву, подбор аналогов, чтение позиции архива | да, при области `archive:read` |
| Сборка сметы (`compose`) | да, при области `archive:write` |
| Список тендеров (`GET /api/v1/tenders/brief`) | да, при области `tenders:read` — только чтение; ключ с ограничением видит только свои тендеры |
| Список позиций тендера (`GET /api/v1/tenders/{id}/positions`) | да, при области `tenders:read` — только чтение; в строках `client_note`, `is_section`, `cost_category_name` |
| Строки позиции (`GET /api/v1/tenders/{id}/positions/{posId}/items`) | да, при области `tenders:read` — только чтение |
| Запись строк BOQ (`POST …/positions/{posId}/items`, `PATCH /api/v1/items/{id}`, `POST /api/v1/positions/{id}/recompute-totals`) | да, при области `tenders:write`; идемпотентности нет — перед повтором читать строки позиции |
| Управление ключами и настройками выдачи API | **нет** — админские эндпоинты только по JWT под ролью administrator/developer |
| Любые другие эндпоинты портала | **нет** — ключу открыт только домен `/api/v1/archive/*` и перечисленные выше маршруты тендера |

Ключ действует **от имени выпустившего пользователя**: строки, созданные агентом,
подписываются им в аудите. Это не безымянный доступ.

## Журнал и отзыв

Каждый вызов по ключу пишется в **Настройки → Доступ к API → Журнал вызовов**: время,
имя ключа, метод и путь, статус, код ошибки, число затронутых строк, признак пробы,
длительность. Тела запросов и секреты не сохраняются.

Неудачные попытки авторизации (401) в журнал не попадают: они отсекаются до него, иначе
любой посторонний мог бы забить таблицу.

Отзыв ключа — кнопка в списке, действует немедленно, при следующем же вызове агент
получит 401. Удаление ключа стирает его из списка, но записи журнала сохраняются.

Отзывайте ключ сразу, если он мог попасть в чат, в скриншот, в git или в чужой профиль
Cursor. Ротация — это просто «выпустить новый, отозвать старый», простоя нет.
