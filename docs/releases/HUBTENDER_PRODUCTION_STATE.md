## AI / OpenRouter — код есть, функция выключена

Код администрирования и подбора номенклатуры присутствует в проде, но **не работает для пользователей**:

- `rollout_mode = off` — единственный переключатель, гейтит все провайдер-вызовы;
- API-ключ сохранён из UI (только AES-256-GCM-шифротекст в БД), вызовов провайдера **0**;
- модель не выбрана, `model_test = required`, бюджет не задан, pilot-пользователей 0;
- обычный пользователь получает `not_allowed` и работает детерминированным подбором, подтверждёнными алиасами и ручным поиском.

Пилот (этап 3.4|0) **не начат**. Блокер — сетевой: с прод-хоста нет исходящего доступа к `openrouter.ai` (с внешних сетей API отвечает нормально). Решается переменной `HTTPS_PROXY` в окружении бэкенда (клиент использует дефолтный транспорт Go, который её уважает) — без правок кода, но это изменение конфигурации прода и требует отдельного решения владельца, после чего повторяются model test и live evaluation.

Откатывать/вырезать AI-код из прода не требуется и не рекомендуется: он инертен при `rollout=off`, а удаление означало бы новый деплой плюс откат миграции.

## История и ветки

Все ветки этапов (`feature/stage-*`, `fix/stage-*`, `feature/ai-key-ui`, `release/hubtender-rc2-staging`) влиты в `main` и удалены — история целиком доступна в `main`. Дальнейшая разработка: ветка от `main` → PR/merge в `main` → сборка и деплой скриптом `scripts/deploy-server.sh`.

## Что осталось в очереди

1. **Решение по egress** для OpenRouter (прокси или отложить пилот).
2. **Этап 3.4|0** — запуск `pilot_individual` по утверждённой директиве (модель `google/gemini-2.5-flash`, бюджет 20 USD/мес, лимиты 10 запросов / 100 строк на пользователя в день, 50 строк на запрос, concurrency 2, 1–2 пилотных пользователя).
3. **Backlog безопасности AI-ключа**: versioned envelope + процедура re-encryption; HKDF с domain separation. До их появления ротация JWT-ключа запрещена без повторного ввода OpenRouter-ключа.
4. **Мелочи**: Chrome-warning про password-поле вне `<form>`; автоочистка `*.map` при деплое; generic `PATCH /tenders/{id}` → 412 при свежем ETag (продуктовые пути не задеты).
